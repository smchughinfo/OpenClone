# Lies

- U-2-Net is all set up to work but it's currently disabled because it doesn't always remove the background perfectly. I believe that is because it just needs a better model file (/U-2-Net/U-2-Net/saved_models/u2net_human_seg/u2net_human_seg.pth) file, which are all over the place online. You could also train one. I just haven't had the time to work on this. You can see U-2-Net working on sites like [this](https://remove-background.net/) so I think it just needs a better model file.
- ElevenLabs is by far the best voice cloning tool I have tried. I've tried many of the [Coqui TTS](https://github.com/coqui-ai/TTS) models as well as [OpenVoice](https://github.com/myshell-ai/OpenVoice). They're all trash compared to ElevenLabs. From what I can tell ElevenLabs might be the ONLY practical TTS available. But this introduces a problem: their [subscription model](https://elevenlabs.io/app/subscription) is kind of hard to pin down. Their [v1/user/subscription](https://elevenlabs.io/docs/api-reference/user/subscription/get) endpoint doesn't really get you all of the way there. So at any time, clone creation or TTS could fail because of some hard-to-specify quota detail. I think this could be worked around with enough effort or by simply purchasing a bigger subscription.
- OpenAI remaining tokens aren't counted either. $10 worth of 4o-mini tokens goes a long way, but if you run out of money on your account, OpenClone has no way of knowing. This would be a simple fix; I just haven't done it.
- Kubernetes does work. You can deploy directly to Vultr using the [/IAC](/Deployment/IAC/) project. But there are problems:
    - They don't let you scale GPU node pools down to 0. So you're gonna have to pay to leave a GPU running 24/7. How small of a GPU, I don't know because they kept disabling my account while I was testing the /IAC project. They make it sound like you're doing something wrong, which is stupid because you literally pay to create each instance. I got pissed off with how arbitrary it was and decided to self-host. So while it does work, it's not dialed in. *I don't think it would be too difficult to port to AWS or Azure now that the process is in place and especially since it's done with Terraform.*
    - The database is not currently scalable. 
        - The design is U-2-NET and SadTalker run on a gpu node pool and then website and database run on a cpu node pool. 
        - For maximum understandability of the system, I want to put the database files on /OpenCloneFS/Database, but I haven't put any effort into doing that. To be clear, it still has /OpenCloneFS mounted, I just haven't put the database files in /OpenCloneFS/Database because there's 10 other scalability concerns that need to be thought through at the same time.
        - No thought into how to properly scale the database has been done. At worst, it could be swapped out with a managed database, but I like the idea of the system being self-contained.
- Development on Linux would need some porting. Obviously the system RUNS on Linux since it's all containerized, but development relies on a few batch scripts that don't have Linux shell equivalents.
- Not so much of a lie, but the Website's data model and Service layer could use a refactor. I think a lot of that code is really good, but some of it is disorganized. [CloneCRUDService.cs](/Website/OpenClone.Services/Services/CloneCRUDService.cs), for example, could use a rethink.
- Development at the end was rushed. I was just trying to get it done. There are definitely bugs and UI nicities on the website that need to be worked out.
